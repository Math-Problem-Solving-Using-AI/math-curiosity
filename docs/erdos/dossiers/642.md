## Statement

Saved page (about 2026-10-16, screen-reader text):

> Let [[f of n]] be the maximal number of edges in a graph on [[n]] vertices such that all cycles have
> more vertices than chords. Is it true that [[f of n is much less than n]] ?

Notes: "A problem of Hamburger and Szegedy. A chord is an edge between two vertices of the cycle which
are not consecutive in the cycle." Chen, Erdős and Staton [CES96]: f(n) << n^{3/2}. Draganić,
Methuku, Munhá Correia and Sudakov [DMMS24]: f(n) << n (log n)^8.

## Our reading

f(n) = the largest number of edges of a simple graph on n vertices in which every cycle C (length
L >= 3) has fewer than L chords, where a chord is an edge of the graph joining two vertices of C
that are not consecutive on C.

Facts we derived ourselves (to be confirmed by computation):
- The property is closed under deleting edges: deleting an edge removes cycles or chords, never adds
  them.
- K4 satisfies it (a 4-cycle has 2 chords). K5 does not (a 5-cycle in K5 has 5 chords). K5 minus an
  edge satisfies it (a 5-cycle there has 4 chords, a 4-cycle at most 2). So f(4) = 6 and f(5) = 9.
  The K4 / K5 check also appears in formal-conjectures pull request #7014 **[read by subagent]**.

Ambiguity: none found. The question itself (f(n) << n) is asymptotic. Small values are data only.

## Formal statement and fidelity

`642.lean` (formal-conjectures commit 2207c54, read by us):
- `CyclesHaveMoreVerticesThanChords G := ∀ v (c : G.Walk v v), c.IsCycle → {e | c.IsChord e}.ncard < c.length`.
- `maxEdges n` = the supremum of edge counts over graphs on `Fin n` with that property.
- Main theorem: `maxEdges =O[atTop] n`.
- Reading: a cycle is a closed walk with `IsCycle`, and `c.length` = number of edges = number of
  vertices. `IsChord` (Mathlib or project definition, **not yet read by us**) should mean "an edge
  of G between two vertices of c that is not an edge of c". The docstring says exactly that.
- `ncard` of a set of `Sym2 V`: finite here, so no junk value.
- Fidelity: matches our reading, **pending a check of `Walk.IsChord`**. The file proves sanity
  lemmas (acyclic graphs qualify, `maxEdges 0 = 0`, `maxEdges n <= C(n,2)`).

## Why it looks low-hanging

Same shape as 585: a function of n, small values computable, none published, OEIS link wanted
(`possible`), certificates checkable by plain code.

## First concrete step and certificate format

1. Checker `bad_cycle(G)`: enumerate all cycles (n <= 10 is fine) and return one with at least as
   many chords as vertices, or none.
2. Search from many edges downwards over graphs up to isomorphism (`geng`, or an orderly generator),
   using closure under edge deletion.
3. Certificates: lower bound = an edge list plus `bad_cycle = none`, recomputed independently; upper
   bound = every graph with f(n)+1 edges, each with an explicit bad cycle and its chord list.
4. Sanity and mutation: f(4) = 6, f(5) = 9. The checker must find the bad 5-cycle in K5.

## Effort and risks

- Cycle enumeration is exponential, but fine up to n = 10 or 11 with pruning.
- Generator trust: cross-check counts as in 585.
- The answer to the actual question (linear or not) will not come from small n.
