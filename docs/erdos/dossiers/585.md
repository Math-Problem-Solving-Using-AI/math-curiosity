## Statement

As on the saved page (content of about 2026-10-16; formulas are screen-reader text):

> What is the maximum number of edges that a graph on [[n]] vertices can have if it does not contain
> two edge-disjoint cycles with the same vertex set?

Notes on the page: Pyber, Rödl and Szemerédi [PRS95] built such graphs with "[[is much greater than n
log log n]]" edges. Chakraborti, Janzer, Methuku and Montgomery [CJMM24] showed at most "[[n times
open paren log n close paren raised to the O of 1 power]]" edges.

## Our reading

g(n) = the largest number of edges of a simple graph G on n vertices such that there are no two
cycles C1, C2 in G with no common edge and the same vertex set.

Facts we derived ourselves (to be confirmed by the first computation, not from a source):
- Two edge-disjoint cycles on the same set S of s vertices use 2s edges inside S, so 2s <= C(s,2),
  which forces s >= 5. So graphs on at most 4 vertices never contain such a pair: g(n) = C(n,2) for n <= 4.
- K5 is the union of two edge-disjoint 5-cycles, so K5 is forbidden. K5 minus an edge has 9 < 10
  edges, so it cannot hold two edge-disjoint 5-cycles: g(5) = 9.
- The property "no such pair" is closed under deleting edges. So g(n) is the largest edge count of a
  graph with the property, and every graph with more edges contains a pair.

Ambiguities: none found in the wording. "Cycle" means a simple cycle of length at least 3, and
"same vertex set" means the two cycles have the same set of vertices (each is a Hamiltonian cycle
of that set).

## Why it looks low-hanging

- It asks for a function of n. Its small values are a finite computation, nobody seems to have
  published them, and the database explicitly marks the OEIS link as "possible", i.e. wanted.
- Every claim gets a certificate that plain code can check (below).
- Small values will not settle the asymptotic question, so this is data, not a solution.

## First concrete step and certificate format

1. Write a checker `has_pair(G)`: for every vertex subset S with |S| >= 5, decide whether G[S] has two
   edge-disjoint Hamiltonian cycles. Exhaustive is fine for n <= 10.
2. For n = 5, 6, ..., search graphs from many edges downwards (the property is closed under deleting
   edges). Generate the graphs up to isomorphism with nauty's `geng` (to be installed), or a custom
   orderly generator cross-checked against published graph counts.
3. Certificates:
   - lower bound g(n) >= m: an edge list with m edges, plus `has_pair(G) = False` recomputed by an
     independent checker;
   - upper bound g(n) <= m: the list of all graphs with m+1 edges (up to isomorphism), each with an
     explicit pair of edge-disjoint cycles on the same vertex set (checking one pair is trivial).
     Completeness of the list rests on the generator, so cross-check its counts with a published
     table of graphs by number of edges.
4. Mutation test: the checker must report the pair in K5, and must report none in K5 minus an edge.

## Effort and risks

- n <= 9: minutes. n = 10: about 12 million graphs in total, so the per-graph check must be fast (C,
  or prune by edge count first). n = 11 probably needs a smarter search.
- Risk: trusting the graph generator (mitigated by count cross-checks). Risk of an off-by-one in the
  definition (fixed by the sanity cases g(4) = 6, g(5) = 9).
- OEIS: AI-generated submissions are forbidden (`../RULES.md`), so any submission must be redone by a
  human.
